# Qlib 策略工作台

本机、单用户的中文 Streamlit 工作台。使用 Qlib 的 Exchange、SimulatorExecutor 和账户系统执行真实日线回测，提供聚宽风格的精简 Python 策略接口。

## 安装和启动

在仓库根目录执行，建议 Python 3.10 及以上：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[ui]'
streamlit run apps/quant_workbench/app.py
```

当前仓库配置监听 `0.0.0.0:31209`，在服务所在机器打开 <http://127.0.0.1:31209>，也可通过已配置的 Docker 端口映射访问。只需本机访问时可显式加 `--server.address 127.0.0.1`。根目录 `.streamlit/config.toml` 同时设置浅色主题。
Qlib 源码安装需要 C++ 编译器以构建现有 Cython 扩展。UI 依赖是可选依赖，不影响原有命令行入口。

1. 在「我的策略」的「新建策略」中选择教学模板，查看课程提示后创建策略。
2. 在编辑页修改代码、保存，设置日期、股票池、本金和费用，点击「运行回测」。
3. 查看进度、停止任务，完成后查看净值、每日持仓、成交、日志及自定义指标。
4. 「回测历史」可打开旧结果或复制代码和配置；复制后运行会使用当时重新扫描的数据。
5. 「数据管理」中刷新正在下载的行情文件，无需重启服务。

代码编辑器自动同步；网络较慢时待右上角运行指示结束再提交。普通文本编辑器可用于无障碍操作或嵌入式编辑器不可用的浏览器。

## 买入持有对照

结果页使用蓝色表示策略、橙色表示买入持有、紫色虚线表示自选基准。收益与风险使用同一张图的上下两个面板，
共享日期轴，上方可在累计收益率与净值之间切换，下方可切换回撤、累计收益差和每日收益。
点击图例可同时隐藏/显示同一账户的上下曲线；拖动缩放、双击复位。详细假设收在「回测假设与对照口径」中，
表格、源码和导出仍保留。自定义指标可选择显示项，默认优先显示价格指标，避免账户金额压平价格曲线。

每次新回测自动用同一份数据快照再运行一个独立的 Qlib 对照账户，采用相同的初始资金、日期和费用。
单标的首日提交 100% 目标仓位；多标的首日各提交 `1/N` 目标仓位，此后不调仓。
与策略相同，按上一日可见价格估算数量、当日开盘成交、收盘估值，保留整数手、资金不足、停牌和缺行情的限制。
实际仓位不保证完全等权，未成交订单不补单，剩余资金留现金；期末不强制卖出。对照不使用策略的 `risk` 参数。

结果页展示策略和对照的扣费净值、回撤、累计收益差，并提供对照账户、成交、持仓 CSV；完整 ZIP 也包含这些表格，
`metrics.json` 保存对照指标和源码。手动指定的市场基准仍独立展示（收盘到收盘的复权价格收益，未扣交易费用）。
累计收益差为策略收益率减买入持有收益率，以百分点表示，并非风险调整后的 Alpha；仓位与风险暴露不同，应结合回撤比较。
旧历史记录保持原样，通过「复制配置」重新运行才会生成对照。对照增加一次回测的计算量，运行期间仍可停止任务。

## 六个经典思路的教学模板

建议按下面的顺序阅读。每个文件都是可以完整粘贴进编辑器的策略源码，带中文注释和参数示例；这些函数由工作台调用，不能当作独立的下载/回测脚本直接运行。
已有的个人策略和历史源码不会因模板更新而被覆盖；重新新建策略才能获得新模板。

| 顺序 / 源码 | 交易规则 | 重点学习 | 参数示例（JSON） |
| --- | --- | --- | --- |
| 1. [买入持有](strategies/buy_and_hold.py) | 第一次有候选时等权提交一次买单，之后不主动调仓 | 初始化、股票池、账户、目标仓位 | `{"risk": 0.95}` |
| 2. [双均线](strategies/moving_average.py) | 短均线高于长均线时持有，否则清仓 | `history`、`groupby`、均值、条件分支 | `{"fast": 5, "slow": 20, "risk": 0.95}` |
| 3. [动量轮动](strategies/momentum.py) | 每 5 个交易日选过去 20 日收益最高的股票 | 因子、字典、排序、调仓计数 | `{"lookback": 20, "topk": 1, "rebalance": 5, "risk": 0.95}` |
| 4. [短期反转](strategies/reversal.py) | 每 5 个交易日选过去 5 日收益最低的股票 | 因子方向、排名与持仓映射 | `{"lookback": 5, "topk": 1, "rebalance": 5, "risk": 0.95}` |
| 5. [布林带均值回归](strategies/bollinger.py) | 跌破下轨持有，回到中轨或以上退出 | 标准差、阈值、延续信号状态 | `{"window": 20, "num_std": 2.0, "risk": 0.95}` |
| 6. [唐奇安通道突破](strategies/donchian.py) | 突破此前 20 日最高价持有，跌破此前 10 日最低价退出 | 高低点、窗口切片、排除被比较行情 | `{"entry": 20, "exit": 10, "risk": 0.95}` |

参数填写在编辑页「交易费用与策略参数 → 策略参数（JSON）」中。空对象 `{}` 使用对应模板的默认值。`risk` 为总目标仓位上限；窗口、持股数、调仓间隔使用整数。
所有信号来自昨日及更早的数据，当前交易日开盘撮合；第一天也尝试计算信号，历史不足则等待。代码中的 `决策前资产` 记录的是决策时账户，结果页主净值图使用收盘后的账户，两者时点不同。

### 每个示例应观察什么

- **买入持有**：看成交记录理解“提交目标”与“实际成交”的区别。只提交一次，整数手、停牌、现金不足导致的未成交部分不自动补单；第一天无候选时才继续等待。
- **双均线**：观察短均线高于长均线时的持仓，均线相等也退出。本例按每日均线状态决策，不要求当天刚出现交叉；震荡行情可能产生反复买卖。
- **动量与反转**：使用相同 `lookback`、`topk`、`rebalance` 对比，能只观察排名方向的差异；再单独改变时间窗口。动量在全体下跌时仍买相对强者，反转在全体上涨时仍买涨得较少者，均没有额外的绝对收益过滤。
- **布林带**：在「自定义指标」看股票池第一只股票的收盘、中轨、上轨和下轨。标准差约定为 `ddof=0`；下轨与中轨之间延续上次信号。这里是特定的均值回归教学规则，并非指标作者认定的通用买点：[John Bollinger 明确说明触及下轨本身不是买入信号](https://www.bollingerbands.com/bollinger-band-rules)。持续下跌时价格可能继续走低。
- **唐奇安通道**：重点看 `previous = group.iloc[:-1]`。被比较的昨日收盘必须与更早的窗口比较；若窗口包含昨日最高价，收盘不可能突破该最高价。本例只实现通道入场和退出，没有完整海龟系统的波动率头寸、加仓和止损规则。

均线、布林带、通道模板给每只股票分配 `risk / 股票池数量` 的固定份额，每日按信号调整，未触发的份额留现金。历史不足或昨日没有有效成交时保留之前的信号；信号是交易意图，并非实际已成交的持仓。股票缺行情时引擎仍可能拒绝订单。
动量、反转模板只在调仓日调整；历史不足或没有候选则保持原持仓。有效候选少于 `topk` 时按实际入选数量等权。没有实时行业、财务查询或外部数据依赖。

### 一次学习实验

1. 先选本地有数据的 3～10 只股票验证行为，动量/反转的 `topk` 要小于股票池数量；这只能验证流程，不能据此判断普遍有效性。
2. 开始日期之前尽量保留至少 21 个行情日，再选择包含上涨、下跌和震荡的观察区间。
3. 固定股票池、日期、本金和费用，分别运行模板；先检查日志与实际成交是否符合条件，再比较收益、回撤和换手。
4. 一次只改一个参数，例如双均线从 `5/20` 改成 `10/30`；把尝试限制在开发区间，另留一段未参与调参的数据做检验。
5. 每个模板都保留一个原始副本，修改副本练习。示例不保证正收益，也不等同于严格模拟涨跌停、流动性和历史股票池的实盘系统。

## 进阶：A股中期动量基线（小资金版）

源码：[stock_momentum_base.py](strategies/stock_momentum_base.py)。在「我的策略 → 新建策略」选择「A股中期动量基线」，
将回测的**初始资金设置为10000元**；策略不会覆盖账户本金。已有策略保存的是源码副本，更新模板不会自动修改这些副本或历史回测。
本版保留动量/趋势信号，调整小资金的选股数量、整数手预算和成本过滤；不连接券商、不处理账户权限。

### 默认规则与参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `lookback` / `skip` | 126 / 21 | `P(t-21)/P(t-147)-1`，t为昨日；完整126日收益，跳过最近21日 |
| `trend_window` | 120 | 昨日复权收盘价严格高于120日均线，且动量为正 |
| `liquidity_window` / `liquidity_topn` | 20 / 800 | 在历史/状态合格股票中按日均成交额选前800，再做趋势/动量过滤 |
| `min_history` | 252 | 需要完整历史市场交易日窗口；停牌、缺行也可能使股票被剔除 |
| `topk` / `buffer` | 3 / 5 | 可负担候选中，合格旧持仓在前5保留，从前3补足，最多3只 |
| `vol_window` / `vol_floor` | 60 / 0.05 | 波动率倒数加权；年化波动下限5% |
| `risk` | 0.80 | 总目标仓位上限；买单规划预留至少20%现金，并估算价格偏差和费用 |
| `stock_cap` / `industry_cap` | 0.30 / 0.50 | 单股30%，已知行业50%；受限部分留现金，不强行满仓 |
| `unknown_industry_cap` | 0.80 | 所有未知行业合并单独限80%，不是伪造行业，也不代表已经分散 |
| `min_trade_value` | 1000 | 新建仓和普通调仓的最低预计金额；0可关闭金额门槛 |
| `rebalance_band` | 0.05 | 普通调整金额至少达到账户资产5%；0可关闭幅度门槛 |
| `max_trade_cost_ratio` | 0.005 | 普通单边调整的预估费用/金额不得超过0.5% |
| `price_buffer` | 0.02 | 按昨日价格为买单预留2%上涨空间，卖出可用资金按下跌2%估算；不是成交滑点模型 |
| `metadata_policy` | `research` | 研究模式或需要完整可见状态的`strict`模式 |

参数可以留空。股票池在界面指定，前800是在**该股票池内**筛选，不会自动扩展全市场。
只用几只个股无法验证广泛选股能力，也不要事后选择涨得好的股票回测。
减少持股数提高了集中度，旧版20只、5%单股上限的研究结论不能直接迁移过来。

### 扩大股票池

回测设置提供「本地 A 股（起点前行情日）」和「自定义股票池」两种来源，新建策略默认使用本地 A 股。
本地模式按回测开始日期之前、最近一个完整行情文件生成固定名单，包含本地沪深主板、创业板、科创板及北交所股票代码；
不使用今天的名单或回测期内收益进行筛选。期间新上市股票不自动加入，改变开始日期会重新生成名单。
它是本地行情覆盖的股票池，不是交易所完整历史成分库；来源日缺行情的股票可能缺席，也未自动剔除 ST 或检查账户权限。

例如开始日期为2026-01-01时，使用2025-12-31行情中的5458只股票。`context.universe` 接收完整名单，
基线每月再从历史/状态合格股票中筛选成交额前800、检查动量和趋势、资金可负担性，最终仍最多持有3只。
页面可查看和下载完整股票池；每次运行保存代码名单、来源日期和文件指纹。
重新打开策略会恢复它最近一次运行的配置；复制旧回测中的自定义股票池会保留原名单，
本地模式则按开始日期重新读取来源文件。旧回测的名单和结果不会被改写。

大股票池建议只预读必要历史：小资金模板默认预读300个市场交易日，覆盖其252日窗口。
「预读历史交易日（0为全部）」只限制回测开始前的文件，回测区间内数据仍完整加载；使用更长窗口时需要相应增大。
没有足够历史时返回已有行情，由策略按历史不足处理。日历仍受原有长缺口分段限制。

1万元分散到数千只股票时，买入持有对照可能连一手都买不到；结果页会提示没有成交。
该对照此时是现金账户，不是全市场等权指数，不能将策略相对它的收益差视为选股能力。

### 整数手、成本和手动调仓计划

1. 用昨日及更早行情计算信号。在单股/行业预算内无法买到一手或最低建仓金额的**新候选**先排除，由后续候选递补。
   旧持仓保留资格只看真实持仓，不能把上月未成交的买单当作持仓。
2. 波动率倒数分配预算，限制单股、已知行业和未知行业，按预留价格空间后的金额向下取整。
   分配后不足最低建仓要求的新候选也会逐一剔除并重新选股，不会向上加一手突破预算。
3. 先规划卖出，再用预计卖出净收入和可用现金规划买入。买单和部分卖单以100股为单位，清仓允许卖出零股。
   分红/拆股后保留原持仓中的零股，部分调仓只增减整数手，不把目标总股数硬凑成100的倍数。
4. 小额、幅度不足或费用过高的普通调整可以跳过。**退出信号、掉出保留范围、目标不足一手以及超限减仓不受小额过滤限制**。
   保留的小额旧仓继续占用现金/总仓位/行业预算，不能先假设已经卖出，再给新股票重复分配这笔资金。
5. 费用取自`context.trading_costs`，与本次回测费率一致：`max(成交额×费率, 最低费用)`。
   这是工作台的费用假设，不是单列佣金/税费的券商账单；实际费用应以账户为准。

例：1万元、单股上限30%，50元的股票一手需要5000元，会跳过而不会突破上限；
10元股票的理论目标3000元，在2%价格余量下可能只能规划200股，剩余现金不会强行分配。

调仓计划保存在`rebalance_plan.parquet`，结果页「调仓计划」可以按日期查看或导出CSV，完整ZIP也包含该表。
字段包含行情截止日、信号排名、操作、参考昨收价、当前股数、变动股数（负数表示卖出）、目标股数/市值/仓位、预计费用和原因。
Notebook 调试时可查看 `context.rebalance_plan`；`context.rebalance_plans` 为累计历史计划。
这些是**当时模拟账户的历史计划**，不能直接作为当前真实账户的订单；手动执行前需要用真实持仓、现金、最新价格重新核对。

仅在本地数据日历每月第一个交易日调仓；月中开始回测会等待下个月。
未成交不自动补单，月内不每日强制再平衡；计划卖单可能因停牌等原因失败，后续买单仍由Qlib检查实际现金。
股价跳空、公司行动和缺行情可能导致实际数量、费用和仓位偏离计划。2%价格余量不保证成交，也不能阻止超过2%的跳空。

### 历史状态缺失如何处理

现有行情没有完整的历史ST、退市整理和行业数据，不会用当前名单替代过去：

- `research`：缺状态的股票允许参与，明确记录缺失数量；所有未知行业合并到独立组，使用`unknown_industry_cap`。
  默认80%是小资金研究的显式假设，**不能证明真实行业分散**。希望保守研究时可设为0.20。
- `strict`：完全没有历史状态时初始化报错；调仓时排除缺少当时可见状态的股票。
  已知ST或退市整理股票在两种模式下都会排除。严格模式不代表具备实盘执行能力。

通过参数提供历史状态，随运行快照保存。例如以下为**格式示例，非真实证券状态**：

```json
{
  "metadata_policy": "strict",
  "security_metadata": {
    "000001.SZ": [
      {"effective_date": "2020-01-01", "known_at": "2020-01-01", "is_st": false, "is_delisting": false, "industry": "银行"}
    ]
  }
}
```

`effective_date`为生效日期，`known_at`为信息可知日期；每条是完整状态，两者都不晚于昨日才可使用。
未来公告和后来修订不会提前进入策略。不要为了提高仓位而伪造行业或ST状态。

### 验证范围

先用真实本金检查买不起一手、手续费、换手与实际仓位，再做跨年份和样本外对照。
工作台的全池买入持有对照可能比本策略仓位高，不能直接把收益差当作选股能力。
当前统一100股交易单位，不模拟各板块差异、准确涨跌停、成交量容量、实时风控或券商持仓核对。

## 本地数据与持久化

默认行情目录为项目根目录下的 `data/market_daily/`，与下载脚本、每日更新任务一致；可在界面修改或设置 `QLIB_WORKBENCH_DATA`。
输入是每日一个 `YYYYMMDD.parquet`，包含 Tushare 字段：

| 字段 | 单位/约定 |
| --- | --- |
| ts_code、trade_date | 股票代码、YYYYMMDD |
| open、high、low、close | 未复权价格，元；必需且大于零 |
| vol、amount | 手、千元；必需且非负 |
| adj_factor | 正数复权因子；必需 |
| pre_close | 可选，昨收价 |
| pe_ttm、pb、total_mv、turnover_rate | 可选估值数据，缺失保留 NaN；市值万元、换手率百分数 |

扫描跳过暂不可读/正在写入的文件。回测固定内容 SHA-256 清单，构建只含本次股票池、基准和所需日期的 Qlib 快照；文件在构建前改变会报错，重新提交即可。原始文件不被修改。
历史读取范围为所选数据段起点到回测结束，允许策略选择任意历史窗口，内存和准备时间随股票池及区间增加。

相邻文件日期间隔超过 20 个自然日时分段，单次回测不能跨段；这只是长缺口检测，不保证所有交易日齐全。数据补齐后刷新会重新分段。首次回测需要至少一个早于开始日的行情日。默认选择最新段的最近 60 个行情日。

运行数据保存在 `.qlib_workbench/`（已忽略版本控制），或由 `QLIB_WORKBENCH_HOME` 指定：

- `index.sqlite`：策略、任务、状态和进度。
- `runs/<id>/`：源码、参数、数据清单、日志、Parquet 结果和 JSON 指标。
- `snapshots/<hash>/`：固定原始行情表及 Qlib 二进制数据，可复用。
- `comparison_cache/<hash>/`：固定买入持有对照的完整结果缓存，可删除后重新计算。

一次运行一个任务；重新加载页面不会重复提交。进程异常退出会在下一次查询时标为失败。停止先发取消请求，5 秒后强制终止任务进程组。取消或失败的结果不展示为完整回测。删除策略保留其历史任务。
CSV/ZIP 可导出收益、持仓、成交、日志和源码参数；ZIP 不包含体积较大的行情快照，原始快照在本地保留。

### 回测性能与结果一致性

一次任务只加载一次原始行情和 Qlib 报价，策略与对照各自使用独立的账户、执行器和报价副本。
行情查询先切日期和字段，单证券价格与复权因子使用预建行索引；每日 `data` 构造避免逐行创建 Pandas Series。
动量基线先检查历史、状态和流动性，再对流动性入围者计算因子；无效波动率会顺次补位，趋势不合格仍不补位。
动量、均值、样本标准差、排序及成交规则保持原口径，不减少交易日、不改用低精度数据。

重复研究时，仅买入持有对照可以命中缓存，策略始终重新执行。缓存区分数据快照、日期、股票池及顺序、资金、
买卖费率、最低费用、对照代码、引擎代码和运行环境；改策略参数可复用对照，改执行条件会重新计算。
缓存校验完整性，失败或取消不发布缓存。Python API 可用 `run_backtest(..., use_comparison_cache=False)` 禁用对照缓存。

任务子进程默认 `PYTHONHASHSEED=0`，也可显式设置此环境变量。Qlib 用集合遍历持仓，固定种子能让浮点求和顺序
在重复任务间一致；不同种子的对照缓存互不复用。它不固定策略自己使用的随机数，随机策略仍需自行设置随机种子。
旧任务仍保留原始结果。结果页和 `metrics.json` 会记录数据快照、行情加载、策略执行、对照计算耗时及是否命中缓存；
首次构建数据快照的耗时另计，新下载数据只影响使用新快照的任务。

2026-11-02 本机实测：5,458 只股票、197 个回测日、300 日预热、1 万元本金，在已有数据快照上，
旧版约 262 秒；优化版复用对照缓存约 68 秒（行情加载 29 秒、策略 40 秒、对照读取 0.05 秒）。
这是本机测量值，会随机器负载和股票池变化。新旧版另以相同 `PYTHONHASHSEED=0` 验证：
全部 8 张结果表及原有收益指标精确一致，包括 39 笔成交；首次计算对照及构建新数据快照的耗时不包含在 68 秒内。

## 策略接口

```python
def initialize(context):
    context.lookback = int(context.params.get("lookback", 20))

def handle_data(context, data):
    df = history(context.lookback, ["close", "volume"], ["000001.SZ"])
    prices = df.xs("SZ000001", level="instrument").close
    if len(prices) >= context.lookback:
        weight = 0.5 if prices.iloc[-1] > prices.mean() else 0
        order_target_percent("000001.XSHE", weight)
    log.info("资产：%.2f", context.portfolio.total_value)
    record(资产=context.portfolio.total_value)
```

| 接口 | 行为 |
| --- | --- |
| initialize(context) | 可选；第一次交易日前调用一次，context 可保存自定义属性 |
| handle_data(context, data) | 必需；每日开盘前调用，data 仅含上一交易日有行情的股票 |
| history(count, fields, securities=None) | 正整数窗口、字段名或字段列表；默认股票池，返回升序 `(datetime, instrument)` 双层索引 DataFrame |
| order_target_value(security, value) | 非负目标金额；同股同日最后一次覆盖 |
| order_target_percent(security, weight) | 0 到 1 的目标仓位，按决策时总资产换算金额 |
| record(**values) | 记录有限数值；同日同名保留最后一个值 |
| log.info/warning/error | 标准 logging 格式及参数，写入本次日志 |

`context.current_dt` 为交易日，`context.params` 为界面填写的 JSON 对象，`context.universe` 为标准化股票池。`context.portfolio` 包含 `cash`、`available_cash`、`total_value`、`positions`；持仓提供实际股数 `total_amount`、价格 `price`、市值 `value`。另提供 `context.cash/total_value/positions` 快捷属性。

代码支持 `SZ000001`、`000001.SZ`、`000001.XSHE` 等形式，接口结果统一采用 Qlib 形式。只能查询和交易本次股票池，基准不会自动加入股票池。

历史字段：open/high/low/close/pre_close、volume（股）、amount（元）、adj_factor，以及输入中存在的估值字段。history 截止上一交易日，价格按可见的最新复权因子调整，成交量反向调整，金额保持不变；不对停牌、未上市和缺失估值填零。请求不存在的字段会报错。窗口按行情日历计算，历史不足时返回已有行。

## 回测假设和指标

- 策略只使用上一交易日及更早的数据；当日开盘撮合、收盘估值。目标数量按前一可见价格估计，开盘跳空可能导致偏离目标仓位。
- 先卖后买，仅做多，不融资；目标加未调整持仓合计不得超过总资产。同日每只股票只形成一笔净调整订单，不能当日往返交易。
- 简化统一采用买入 100 股整数手、卖出清仓允许零股；不刻画板块差异。现金、手续费、持仓和交易手数由 Qlib 约束，无法成交的订单当日失效。
- 没有行情或成交量为零不交易。持有证券缺行情时沿用 Qlib 的已有估值，退市清算未单独建模。
- 默认买入费率 0.0005、卖出费率 0.0015、最低费用 5 元，是可编辑的固定回测假设，不是历史税费表。零费率也可运行。
- 无滑点、冲击及成交量容量约束，不模拟准确涨跌停、历史 ST 或新股特殊规则。
- 使用复权收益口径，复权持仓映射至实际股数；分红/拆股不单列现金流水。该口径不能替代逐笔公司行动账本。
- 默认无基准。选择基准时必须有完整对齐的本地价格及前一交易日数据；不会自动生成指数行情。
- 累计收益按扣费后净资产/初始资金计算；年化按 252 个交易日复利；波动与夏普用日收益样本标准差，无风险利率为零。
- 回撤峰值包含初始净值 1；零波动或样本不足时夏普显示不可计算；超额收益为策略累计收益减基准累计收益。

这是精简接口，不提供完整 jqdata、财务查询 DSL、分钟线、实盘或模型训练入口。子进程用于任务控制，不是安全沙箱；只运行本人可信策略，不要将服务公开给不可信用户。
